# Finance Creative Pipeline

Use the deterministic local runtime for web collection, ChatGPT Web generation, and post-generation visual decomposition. Use Figma MCP tools only after the runtime reaches `awaiting_figma`; sync only `ready` directions that each have a valid `preview.png`, `layers.json`, and `layers/decomposition-report.json`.

## Run order

1. Ensure dependencies exist with `npm install` in the plugin root when `node_modules` is absent.
2. For first use or expired sessions, run `node scripts/setup-login.mjs` in a visible terminal and let the user complete both logins. Login setup always forces a visible browser.
3. Run `node scripts/run.mjs` for the normal 10-reference/10-direction workflow, add `--test` for the 1-reference/1-popup trial, or use `--types popup,banner,float` for an isolated three-type validation run with one reference and one generated direction per requested type. Normal and scheduled runs use a visible dedicated Chrome by default because Huaban rejects headless mode and ChatGPT does not reliably preserve its authenticated session in the macOS background-launch mode.
4. Read the emitted `runDir`, `figma-manifest.json`, and the `layers.json` plus `layers/decomposition-report.json` referenced by each `ready` direction. Do not start Figma work unless the run status is `awaiting_figma`; retained failures are audit records and must not be synced.
5. Follow [figma-sync.md](references/figma-sync.md) to create the dated section, upload the preview and extracted assets, rebuild OCR text natively, and verify screenshots.
6. After all Figma nodes and images are verified, run `node scripts/mark-figma-complete.mjs --date YYYY-MM-DD --section-id NODE_ID --section-name "SECTION_NAME" --direction-ids ID1,ID2 --uploaded-assets N`. Do not mark the run complete before visual verification.

## Hard requirements

- Use the persistent Chrome profile stored outside the plugin. Never export or share it.
- Keep normal, scheduled, and resumed runs in `browser.mode: "visible"` so Huaban and ChatGPT share the same authenticated persistent-profile behavior. Do not automatically hide or minimize the browser. Treat `headless` and `background` as opt-in diagnostic modes only: Huaban may reject headless mode with HTTP 405, while ChatGPT may lose its authenticated session in the macOS background-launch mode.
- Launch the dedicated Chrome process at most once per workflow run. Hold the global workflow lock until the browser closes, create the Huaban, Pin-detail, and ChatGPT tabs together at startup, and reuse them for all directions and retries. If another run is already active or the browser fails, stop instead of opening a second Chrome window.
- Use ChatGPT Web for analysis and image generation. Do not call Codex image generation as a fallback.
- Create or reuse exactly one dated ChatGPT project named `<chatgpt.projectNamePrefix> YYYY-MM-DD` for each run date. Persist the verified project URL in `figma-manifest.json` and `run.json`; on resume, reopen it instead of creating another project. If Projects is unavailable or the project URL cannot be verified, stop instead of falling back to ungrouped root-level chats.
- Use exactly one project chat per creative direction. Keep reference analysis, preview generation, semantic layer JSON, every separate transparent-asset extraction, correction attempts, and direction retries in that same chat. Persist each direction chat URL immediately after it becomes available and reopen it when resuming. Start the next chat only when moving to the next direction; never create separate decomposition or per-asset chats.
- Explicitly rename every direction chat through ChatGPT's conversation menu and persist the verified title in the manifest. Use type-local numbering: `弹窗1` through `弹窗6`, `Banner1` through `Banner2`, and `浮窗1` through `浮窗2`; isolated validation runs start each included type at 1. Do not rely on ChatGPT's auto-generated titles.
- Before sending any reference-analysis prompt, upload through ChatGPT's image-specific input and verify that every expected filename has a visible removable attachment, every image thumbnail has rendered, and the send control is enabled. A file-input assignment or fixed delay alone is not proof of delivery. If ChatGPT reports that reference images are missing, clear the composer attachments, re-upload all references, and retry; never continue generation from an unverified analysis.
- Generate exactly one complete preview image, then create one separate ChatGPT image task and one separate PNG file for each accepted complex raster asset. Never combine multiple assets into one sheet or image.
- For popup directions, generate only the popup body: the card, its shadow, attached or overflowing hero, internal content, CTA, and popup-owned decorations. Leave only a clean uniform safety margin outside it. Never generate an App page, search bar, navigation, bottom tabs, feeds, page cards, charts, or blurred interface behind the popup.
- After each preview is saved, send it back to ChatGPT Web for semantic review. Save layer roles, normalized boxes, editable types, OCR copy, z-order, confidence, and a short `assetPrompt` for every complex raster asset to `layers.json`.
- Keep the semantic-review response readable in ChatGPT: request exactly three display lines consisting of `DECOMPOSE_START`, one complete minified JSON line, and `DECOMPOSE_END`. Do not remove layer data or rely on unsupported collapsible HTML; parse the compact JSON and save it normally to `layers.json`.
- Classify conservatively. Only complex hero visuals, 3D objects, people, mascots, or illustrations that cannot be faithfully rebuilt with Figma text and basic vectors may use `raster`. Cards, buttons, ordinary icons, charts, lines, light trails, and simple decorations must remain native `vector` or `text`. Do not increase the asset count for its own sake.
- Describe every ordinary functional icon as `kind: "icon"` with `icon.query` containing two to four concise English semantic terms, `icon.style` set to `line` or `fill`, and `icon.color` copied from the preview. During Figma reconstruction, search the bundled Remix Icon package first and import the closest semantically correct official SVG as an editable vector. Never invent an icon-library filename, trace an icon by hand, or leave a generic rectangle, sparkle, chevron, or improvised path when Remix Icon has a suitable match. Do not replace logos, brand marks, complex illustrations, or unique campaign symbols with library icons.
- For each raster layer, start a separate ChatGPT task with the complete preview and a concise request to extract only that element, preserve its original shape, proportions, color, lighting, and details, and return a true transparent PNG. Never ask ChatGPT to redesign, improve, or create a multi-asset sheet.
- Local processing may trim transparent margins and measure Alpha/border quality only. Never run local foreground segmentation, Apple Vision matting, downloaded matting models, rectangle crop fallbacks, or LLM-authored polygon masks.
- Reject any generated asset that lacks real Alpha, has a colored/checkerboard/semitransparent full background, is empty, mostly fills the canvas, or touches the image boundary. Retain rejected attempts for inspection, retry only that asset, and never upload invalid assets.
- Treat `decomposition-report.json` warnings and limitations as binding evidence. Visually compare every accepted asset with the preview and reject material changes in shape, proportions, color, lighting, or details even when Alpha checks pass.
- Do not bypass login, CAPTCHA, WAF, download restrictions, paid assets, or security interstitials.
- Collect references through type-specific search plans: six popup references for six popup directions, two Banner references for two Banner directions, and two floating-window references for two floating directions. Give each direction exactly one matching reference image. Rotate through several matching keywords with a per-keyword cap; never use popup queries as Banner or floating-window sources. Every Banner query must explicitly combine a finance category with `banner` or `横幅`, prioritize simple horizontal compositions, and avoid generic promotion-only queries. Every floating-window query must combine a finance category with a complete floating-entry form such as `活动浮窗`, `福利入口`, `活动浮标`, or `活动挂件`; do not use bare `浮窗`, `小浮窗`, `悬浮窗素材`, or `悬浮按钮` queries.
- Audit popup references by title and visual structure. The title must indicate a popup/modal form or a finance-operations context and must not describe an atomic element, background, button, sticker, poster, or full page. Opaque screenshots must contain a visually distinct modal subject over a dimmed or contrasting surrounding page; transparent references must contain a standalone complete subject. Keep the configured minimum-width gate.
- Audit Banner references by title and visual structure. Require both finance-business semantics and finished horizontal marketing semantics such as Banner, horizontal cover, first image, advertisement, promotion, or campaign. Reject unrelated industries and atomic backgrounds, elements, buttons, templates, or mockups. Require a horizontal aspect ratio of at least 1.5 and keep the configured minimum-width gate.
- Audit floating references by content rather than pixel dimensions. Require the Pin title to indicate both a complete floating-entry form and finance/operations context, reject titles that indicate backgrounds, borders, plain buttons, text stickers, or full pages, and require the downloaded image to contain a standalone subject with real transparent margin. Do not apply the normal 720 px minimum width or an aspect-ratio limit to floating references. Record content rejections and metrics in persistent and daily `reference-rejections.json`, skip rejected Pins across runs, and continue searching until the floating quota is full.
- Before downloading, reject Pin IDs recorded in the persistent `reference-history.json` ledger and scroll deeper for unseen results. After download, reject only the same image: an identical SHA-256, or an identical aHash with a matching aspect ratio. Do not reject merely similar compositions or templates.
- Open each accepted Pin detail page and select the highest-resolution URL exposed by its visible main image through `currentSrc`, `src`, or `srcset`. Require the configured minimum width (720 px by default) for popup and Banner references only; floats are content-gated and may be smaller. Retain the reference type, search query, list thumbnail URL, selected image URL, dimensions, and Pin source URL. Never synthesize or rewrite CDN URLs to obtain restricted originals.
- Keep generated content brand-neutral and reject real logos, real brand names, copied copy, guaranteed approvals, fixed returns, or fabricated regulatory endorsements.
- Resume from `run.json` and `figma-manifest.json`; never duplicate successful directions or Figma date sections. After cached references are re-audited, read the daily `reference-rejections.json`; if a `ready` direction cites a newly rejected source URL, invalidate and regenerate only that direction with its newly accepted replacement reference, including its spec, preview, semantic layers, and transparent assets. Keep every unrelated complete direction intact.
- Give reference analysis its own budget of at most two total attempts, each with a five-minute limit. If both fail, record `stage: "analysis"`, continue later directions, and append that direction once at the end of the current ChatGPT queue for one final analysis attempt. Never enqueue a second final retry.
- Give preview generation at most two total attempts, each with a five-minute wait limit. Record an exhausted direction in `figma-manifest.json.failures` and continue later directions.
- Give semantic decomposition its own budget of at most two total attempts, each with a five-minute wait limit. Once `preview.png` is valid, never regenerate it because decomposition timed out. On a missing response, reload the same saved direction chat, briefly check for a delayed reply, then reupload the existing preview and resend only the semantic decomposition prompt.
- Give each separate transparent PNG asset at most two total attempts, each with a five-minute wait limit. This budget is independent of semantic decomposition and must never be nested inside its retries. Reuse accepted assets and retry only the failed asset.
- Snapshot historical failed directions at run start, process them after all new pending directions, and give each historical direction only one total attempt for its remaining ChatGPT stage. After that final historical pass, end the day's ChatGPT phase. Preserve remaining failures for audit, set the run to `awaiting_figma` when at least one verified `ready` direction exists, and continue Figma sync using only those ready directions.
- Login expiry, CAPTCHA, WAF, security checks, access denial, and permission errors are user-action blockers, not direction failures. Stop immediately and notify the user instead of retrying or skipping past them.
- For Figma writes, load and follow `figma-use` and `figma-generate-design`; work incrementally and return every created or mutated node ID.
- Preserve the two-up contract in Figma: `Preview` is the visible flattened design on the left, while `Editable` on the right must visibly render the reconstruction from accepted separate `chatgpt-transparent-asset` PNGs plus native text and vectors. Keep `Visual Base` locked but hidden as an inspection reference; never show the same flattened preview on both sides. Popup `Editable` canvases stay transparent and contain only the popup body; do not rebuild page or App-interface backgrounds, and ignore legacy popup layers such as `Background/AppInterface`, search bars, navigation, bottom tabs, feeds, and page cards. Banner and float directions may use the first `spec.json` palette color or their native background geometry. Place transparent assets inside `assetPlacement.box` with aspect ratio preserved, `contain` sizing, and center alignment; use `assetBboxPx` only for older reports. Never upload rejected assets.
- Treat editable-side visual QA as a completion gate. Fix or hide duplicated background OCR, text that exceeds its declared bbox, malformed generic vector placeholders, incorrectly matched or distorted Remix Icons, residual text showing through translucent cards, and incorrect z-order. Do not hide `Editable Elements` to make the screenshot pass, and do not mark Figma complete while the right side is identical to the preview or visibly broken.

## Recovery

- If the runtime reports missing login, run setup and then rerun the same command.
- Retain failure screenshots and continue later directions. New directions receive the two-attempt stage budgets above; historical failures run last with one final attempt. Remaining failures do not block verified ready directions from continuing to Figma.
- If Figma fails, do not rerun collection or generation. Resume from the existing manifest.
- If the 10:30 run was missed, notify once and wait for explicit user approval before launching a catch-up run.

## User configuration

Read or edit `~/Library/Application Support/Codex/finance-creative-pipeline/config.json`. Keep personal values there rather than in the shared plugin.
