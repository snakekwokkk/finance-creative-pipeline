# Finance Creative Pipeline

Use the deterministic local runtime for web collection, ChatGPT Web generation, and post-generation visual decomposition. The runtime emits a `direction_ready` event after each direction has a valid `preview.png`, `layers.json`, and `layers/decomposition-report.json`; Figma may consume that direction while the runtime continues the next one. Sync progress belongs only in `figma-sync-state.json`, never in the producer-owned `figma-manifest.json`.

## Run order

1. Ensure dependencies exist with `npm install` in the plugin root when `node_modules` is absent.
2. For first use or expired sessions, run `node scripts/setup-login.mjs` for Huaban plus ChatGPT. Let the user complete both logins in the visible browser.
3. Run `node scripts/run.mjs` for the normal Huaban 10-reference/10-direction workflow and keep its process session active. Add `--test` for the 1-reference/1-popup trial, use `--types popup,banner,float` for an isolated three-type validation run, or use `--types popup,banner,float --collection-only --visible` to collect and content-audit one Huaban reference per type before stopping without generation, decomposition, or Figma work. Normal and scheduled runs use a visible dedicated Chrome by default.
4. On each emitted `direction_ready` event, read the current manifest entry and its `layers.json` plus `layers/decomposition-report.json`, then run `node scripts/figma-sync-progress.mjs inspect --date YYYY-MM-DD`. Sync only the event's validated ready direction; retained failures are audit records and must not be synced.
5. Follow [figma-sync.md](references/figma-sync.md). Record the reused or created dated Section once, mark the direction `syncing` before Figma writes, persist its Frame ID immediately after creating or resolving it, then record the uploaded asset count and `qa_passed` only after native-resolution geometry and visual-difference QA produce a passing report.
6. Continue polling the still-running local process while Figma work proceeds. A later direction may generate and decompose in Chrome while the previous ready direction is written and checked in Figma; never launch a second workflow or Chrome process.
7. After the local runtime reaches `awaiting_figma`, drain any remaining pending ready directions. Then run `node scripts/mark-figma-complete.mjs --date YYYY-MM-DD`; it must refuse completion unless every current ready artifact revision has a matching `qa_passed` record.

## Hard requirements

- Use the persistent Chrome profile stored outside the plugin. Never export or share it.
- Keep normal, scheduled, and resumed runs in `browser.mode: "visible"` so Huaban and ChatGPT share the same authenticated persistent-profile behavior. Do not automatically hide or minimize the browser. Treat `headless` and `background` as opt-in diagnostic modes only: Huaban may reject headless mode with HTTP 405, while ChatGPT may lose its authenticated session in the macOS background-launch mode.
- Launch the dedicated Chrome process at most once per workflow run. Hold the global workflow lock until the browser closes, create the selected source search tab, its detail tab, and the ChatGPT tab together at startup, and reuse them for all directions and retries. If another run is already active or the browser fails, stop instead of opening a second Chrome window.
- Treat `figma-manifest.json` as producer-owned. Figma orchestration must never add node IDs or sync status to it while generation is active. Use `figma-sync-state.json`, whose per-direction artifact revision prevents a stale reconstruction from being accepted after regeneration.
- Create or reuse the dated Figma Section idempotently and record it with `figma-sync-progress.mjs section`. Before mutating a direction, run `start`; immediately after creating or resolving its Frame, run `node`; after screenshot QA, run `complete`. Record a failed write or QA gate with `fail`. Reuse a recorded direction Frame when retrying instead of creating a duplicate.
- Use ChatGPT Web for analysis and image generation. Do not call Codex image generation as a fallback.
- Create or reuse exactly one dated ChatGPT project named `<chatgpt.projectNamePrefix> YYYY-MM-DD` for each run date. Persist the verified project URL in `figma-manifest.json` and `run.json`; on resume, reopen it instead of creating another project. If Projects is unavailable or the project URL cannot be verified, stop instead of falling back to ungrouped root-level chats.
- Create or reuse the dated ChatGPT project before reference collection. Keep the three optional content-audit chats named `采集筛选-弹窗`, `采集筛选-Banner`, and `采集筛选-浮窗` inside that same project, persist their URLs in `reference-audit-chats.json`, and reuse them on resume. Candidate audits submit fresh public Huaban image URLs rather than image attachments. Never create root-level audit or generation chats.
- Use exactly one project chat per creative direction. Keep direct reference-conditioned preview generation, semantic layer JSON, optional complex-frame reconstruction, and direction retries in that same chat. Persist each direction chat URL immediately after it becomes available and reopen it when resuming. Start the next chat only when moving to the next direction; never create separate decomposition or asset chats.
- Explicitly rename every direction chat through ChatGPT's conversation menu and persist the verified title in the manifest. Use type-local numbering: `弹窗1` through `弹窗5`, `Banner1` through `Banner3`, and `浮窗1` through `浮窗2`; isolated validation runs start each included type at 1. Do not rely on ChatGPT's auto-generated titles.
- Upload each direction's reference through ChatGPT's image-specific input exactly once on the normal successful path. Verify the expected filename, visible removable attachment, rendered thumbnail, and enabled send control, then use that same message to ask ChatGPT to analyze the reference internally and directly generate the preview. Do not request or display an intermediate analysis, design spec, image prompt, or JSON, and do not upload the reference again in a separate preview-generation turn. On an ordinary generation retry, reuse the reference already present in that direction chat; re-upload only when ChatGPT explicitly reports that the reference image is missing.
- For a new direction, upload the reference in the dated project's new-chat composer and make the direct-generation request the first and only chat-creating message. Do not send a READY, bootstrap, placeholder, or other text-only turn before the reference-conditioned generation request. Persist the resulting conversation URL immediately after that first formal message is observably submitted and before monitoring its output.
- Generate exactly one complete preview image. First extract complex raster visuals directly from that preview's source pixels. When a large connected framework encloses multiple editable text, button, card, or decoration layers and source-pixel extraction cannot remove those overlays, ChatGPT may reconstruct only that framework in the same direction chat by removing the overlays and filling the hidden material. Do not re-upload the reference or preview for this fallback. Keep visually connected hero objects together as one raster group, and separate only independently movable complex visuals.
- Treat the Huaban reference as visual direction rather than a template. Preserve a similar financial visual category, material feel, color relationship, and information hierarchy where useful, while redesigning concrete shape details, copy, and local layout rather than copying the full design.
- For popup directions, generate only the popup body: the card, its shadow, attached or overflowing hero, internal content, CTA, and popup-owned decorations. Leave only a clean uniform safety margin outside it. Never generate an App page, search bar, navigation, bottom tabs, feeds, page cards, charts, or blurred interface behind the popup.
- After each preview is saved, request semantic review in the same ChatGPT conversation without uploading the preview again. Save layer roles, normalized boxes, editable types, OCR copy, z-order, confidence, and a short `assetPrompt` for every complex raster asset to `layers.json`.
- Keep the semantic-review response readable in ChatGPT: request exactly three display lines consisting of `DECOMPOSE_START`, one complete minified JSON line, and `DECOMPOSE_END`. Do not remove layer data or rely on unsupported collapsible HTML; parse the compact JSON and save it normally to `layers.json`.
- Detect semantic-review completion from the latest valid non-empty `DECOMPOSE_START`/`DECOMPOSE_END` block across the saved conversation, not from one fragile assistant-message selector or the disappearance of ChatGPT's stop control. Ignore the empty example in the user prompt. On resume and before every retry, scan the existing direction chat first and consume its newest complete marked JSON immediately; never submit another decomposition request when a valid result is already present.
- Classify by an explicit 95% native-fidelity threshold. Complex hero visuals, 3D objects, people, mascots, illustrations, complex cards or frameworks, shadows, glass, textures, gradient folds, embossed badges, glossy envelopes, and other objects that cannot be faithfully rebuilt with Figma text and basic vectors at 0.95 fidelity must use a text-free `raster` base; only simple geometry, ordinary icons, charts, lines, text, and plain buttons that can reach at least 0.95 may remain native `vector` or `text`. Keep connected complex hero objects in one raster asset so their geometry cannot drift. Split only spatially independent complex objects; do not include editable copy in the raster asset, and do not increase the asset count for objects that are genuinely simple.
- Describe every ordinary functional icon as `kind: "icon"` with `icon.query` containing two to four concise English semantic terms, `icon.style` set to `line` or `fill`, and `icon.color` copied from the preview. During Figma reconstruction, search the bundled Remix Icon package first and import the closest semantically correct official SVG as an editable vector. Never invent an icon-library filename, trace an icon by hand, or leave a generic rectangle, sparkle, chevron, or improvised path when Remix Icon has a suitable match. Do not replace logos, brand marks, complex illustrations, or unique campaign symbols with library icons.
- For each raster layer, use its tight bbox plus a small safety margin and run the bundled source-pixel background matting extractor first. Local processing may infer Alpha from the surrounding background, trim transparent margins, and measure Alpha/border quality. If the source crop is usable but tight or touches its crop boundary, retain it with explicit warnings instead of discarding a legitimately small element.
- Use ChatGPT reconstruction only for large composite frameworks that contain multiple declared editable layers or when no usable source-pixel asset can be recovered. Ask it to remove text and overlays, fill the occluded material, and place the isolated subject on a uniform background; locally derive Alpha afterward. Record `engine: chatgpt-reconstructed-matting`, `sourcePixelExact: false`, and the retained source fallback when available. Never describe a reconstructed asset as source-pixel exact.
- Reject only assets that are empty, lack usable Alpha after local matting, or have no recoverable subject. Continue processing every other raster after one fails. A report may be `partial` for producer-side audit when at least one complex asset is usable, but `partial` must not pass Figma QA when any missing critical layer leaves a visible hole or changes the composition. Retain every accepted asset and every failed attempt for audit.
- Treat `decomposition-report.json` warnings and limitations as binding evidence. Accepted source assets report `engine: native-source-pixel-matting` and `sourcePixelExact: true`; accepted reconstructed assets report `engine: chatgpt-reconstructed-matting` and `reconstructedByChatGpt: true`. Tight crops and source fallbacks may list `suppressesLayerIds` so Figma does not duplicate content already baked into the retained raster.
- Do not bypass login, CAPTCHA, WAF, download restrictions, paid assets, or security interstitials.
- Collect from Huaban only. Use Chinese type search plans: five popup references, three Banner references, and two floating-window references. Give each direction exactly one matching image and rotate keywords after at most three candidates. Floating-window references may be a complete entry, a single finance-related 3D/illustration asset, or an asset-plus-button composition.
- Treat source titles as weak metadata. Hard-reject only titles that explicitly identify a background, template, full page, atomic element, or another clearly invalid form. Never hard-reject a title only because it names another industry. For floats, buttons, badges, coins, red envelopes, 3D assets, and illustrations are valid standalone references when they carry an operational signal. Route empty titles, filenames, `IMG_*`, and titles missing finance or format terms to image-content review instead of rejecting them.
- For every missing direction, scan at most 30 unseen Pins across rotated queries and resolve fresh public main-image URLs from the visible Huaban detail page. Submit exactly six URLs per new ChatGPT Web review batch; never submit an active-scan tail batch of one to five URLs. Allow at most three completed review batches per creative type per dated run, including batches completed before a resume, so each type reviews at most 18 candidates. After the third batch, discard any unsubmitted tail queue, retain however many approved references that type produced, and continue immediately to the next type; do not keep searching to fill the nominal quota. Before the third batch, persist an incomplete local queue and add later candidates until it reaches six. The only exception is recovery of a legacy batch that was already submitted before this rule; consume its existing marked response without resending it. Keep popup and Banner minimum width at 720 px by default and require Banner aspect ratio of at least 1.5 from the visible main image before review. Download at most eight ChatGPT-approved candidates per missing direction for final pixel, hash, duplicate, and Alpha checks. Floating references have no normal width, aspect-ratio, or Alpha gate at collection time: accept a compact financial 3D/illustration subject on a flat canvas for later transparent extraction, while still rejecting obvious backgrounds and complete pages.
- Make the final reference decision from visible image content. Require `imageAccessible`, `typeMatch`, `completeDesign`, and `financeRelevant`; when all four are true, accept the candidate regardless of `score`, `structureValid`, or `usableReference`. Treat any visible Arabic numeral, the Chinese character `元`, `¥`, `$`, `%`, explicit amount, coins, coupons, dashboard or data-chart visuals, trend or upward arrows, red envelopes, or interest/fee wording as a qualifying broad financial or operational signal. For popups require a complete modal/card and content hierarchy; for Banners require a finished horizontal operations composition; for floats require a complete independent operations entry or campaign subject. Do not reject otherwise valid travel, ecommerce, membership, dining, utility, or other-industry material merely because of its industry. Reject backgrounds, empty templates, atomic buttons/icons/elements, QR-code subjects, or clearly low-quality materials. Keep score and soft signals only for audit and ordering, never as acceptance vetoes.
- Do not download content-rejected or inaccessible URL candidates. Record their Pin, source, direct image URL, title, visual score, audit chat, accessibility status, and reasons in the rejection ledger. Download only ChatGPT-approved candidates, delete any downloaded file that later fails pixel or duplicate checks, and move only selected originals into `references/`; each direction still receives exactly one reference. Reuse accepted `contentAudit` results on resume and re-review cached references that predate content auditing.
- Give content-review handling at most two attempts per batch under the submit-once recovery lock; this is separate from the three-batch-per-type ceiling. Login expiry, CAPTCHA, WAF, project-access, and permission errors remain global user-action blockers. If three batches or the scan/download budgets end without filling the type quota, retain the references that passed, record each missing direction as `stage: "collection"`, and continue remaining directions and all valid Figma work. Never reuse another direction's reference to fill the gap.
- Verify every ChatGPT prompt submission from observable composer clearing, a new user-message node, or creation of the expected conversation URL. Execute at most one submit action for each filled prompt. If that action is not visibly confirmed, treat its outcome as ambiguous, stop immediately, and recover only by reading the existing conversation; never try another button selector, Enter, direct DOM click, or platform shortcut for the same prompt.
- Apply the same durable submit-once lock to reference audits, preview image generation, semantic decomposition, and optional reconstructed raster generation. Persist each stage's prompt identity, pre-submit visible-image sources, saved-conversation image pointers, and assistant-message baseline before clicking Send. A timeout or ambiguous submission must keep that stage locked; every retry and restart must reopen the saved conversation and continue monitoring against the original baseline instead of recomputing a new baseline or sending again. Monitor both rendered DOM images and authenticated saved-conversation image pointers, and download a valid saved image even when the page has not rendered its `<img>` element yet. Permit a new prompt only after ChatGPT explicitly reports generation failure, a complete marked JSON response is structurally invalid, or a downloaded reconstructed image is locally and conclusively rejected. Never click Stop merely because a submitted image exceeded the local wait window.
- Detect content-review completion from the latest valid `REFERENCE_AUDIT_START` / `REFERENCE_AUDIT_END` JSON block whose Pin IDs exactly match the current batch. Poll rendered page text locally once per second by default, but fetch the authenticated saved-conversation payload no more often than once every 15 seconds; both intervals are configurable. Keep at least 30 seconds between audit-chat prompt submissions. If ChatGPT visibly reports that operations are too frequent, persist the current batch and rate-limit state, wait the configured 10-minute cooldown without submitting anything, then reopen the same chat. Continue passive monitoring when the original click may have been accepted; only when the prompt remains unchanged in the ready composer and the frequency notice proves that the click was rejected may the same prompt be submitted once after cooldown. Permit only one automatic rate-limit recovery per batch; if the notice remains, stop for later resume. Remain independent of assistant-message counts and the stop control, and perform a final five-second boundary scan before declaring timeout. Surface a complete but invalid marked block immediately instead of waiting for timeout. Once a complete valid marked response is captured, stop only its residual active-generation state before submitting the next batch so the send control is released. Require `imageAccessible: true` before any candidate can pass. Before a new audit submit action, atomically persist the exact Pin IDs as an armed idempotency lock. Before submitting or retrying a URL batch, scan the existing audit chat and consume a completed matching response immediately. An armed, pending, timed-out, ambiguously submitted, or completed batch can only be passively monitored and must never be resubmitted, including after restart. A different pending batch in the same audit chat blocks all new submissions until it is resolved.
- Before downloading, reject previously recorded Huaban Pin IDs in `reference-history.json` and scroll deeper for unseen results. Reject identical images by SHA-256, the same stable Huaban asset key, or a matching combined aHash plus 256-bit dHash fingerprint and aspect ratio. Never reject on aHash and aspect ratio alone. Record every duplicate decision with its matched Pin and fingerprint reason instead of silently discarding it.
- Open each candidate source detail page in the locally authenticated persistent Chrome and select the highest-resolution fresh public URL exposed by its visible main image through `currentSrc`, `src`, or `srcset`. Send that URL to ChatGPT for content review without sharing Huaban cookies or account credentials. Download it only after approval. Require the configured minimum width (720 px by default) for popup and Banner references only; floats are content-gated and may be smaller. Retain the reference type, search query, list thumbnail URL, selected image URL, dimensions, and source URL. Never synthesize Huaban CDN URLs.
- Keep generated content brand-neutral and reject real logos, real brand names, copied copy, guaranteed approvals, fixed returns, or fabricated regulatory endorsements.
- Resume from `run.json` and `figma-manifest.json`; never duplicate successful directions or Figma date sections. After cached references are re-audited, read the daily `reference-rejections.json`; if a `ready` direction cites a newly rejected source URL, invalidate and regenerate only that direction with its newly accepted replacement reference, including its preview, semantic layers, and transparent assets. Keep every unrelated complete direction intact. Treat legacy `stage: "analysis"` failures as pending direct-generation work with the normal generation attempt budget.
- Give preview generation at most two total attempts, each with a five-minute wait limit. Record an exhausted direction in `figma-manifest.json.failures` and continue later directions.
- Give semantic decomposition its own budget of at most two total attempts, each with a five-minute wait limit. Once `preview.png` is valid, never regenerate it because decomposition timed out. On a missing response, reload the same saved direction chat and scan for a complete marked result before any resend. Only when no valid result exists may the runtime reupload the existing preview if needed and resend the semantic decomposition prompt.
- Attempt every declared raster independently. Reuse accepted source or reconstructed assets with supported provenance, retry only the failed asset, and never let one failure prevent later assets from being attempted. Partial directions may continue when they retain at least one usable complex asset.
- Snapshot historical failed directions at run start, process them after all new pending directions, and give each historical direction only one total attempt for its remaining ChatGPT stage. Each newly verified direction may enter the independent Figma queue immediately. After the final historical pass, end the day's ChatGPT phase, preserve remaining failures for audit, and set the run to `awaiting_figma` when at least one verified `ready` direction exists so any remaining Figma queue can drain.
- Login expiry, CAPTCHA, WAF, security checks, access denial, and permission errors are user-action blockers, not direction failures. Stop immediately and notify the user instead of retrying or skipping past them.
- For Figma writes, load and follow `figma-use` and `figma-generate-design`; work incrementally and return every created or mutated node ID.
- Treat `preview.png` as the sole visual truth for the Figma reconstruction. Convert every normalized `{x,y,width,height}` bbox to pixel coordinates against the declared preview canvas and place each editable layer at those exact coordinates and dimensions; do not manually approximate, re-layout, center, distribute, optimize spacing, or reinterpret the composition. Keep artwork canvases and every descendant artwork group free of Auto Layout because it changes absolute coordinates; Auto Layout is allowed only on out-of-canvas wrappers such as the two-up presentation row and metadata stack.
- Preserve the two-up contract in Figma: `Preview` is the visible flattened design on the left, while `Editable` on the right must visibly render the reconstruction from accepted `native-source-pixel-asset` and `chatgpt-reconstructed-asset` PNGs plus native text and vectors. Skip every native layer ID listed in an accepted raster's `suppressesLayerIds`; that content is already baked into the retained tight-crop or fallback image. Keep `Visual Base` locked but hidden as an inspection reference; never show the same flattened preview on both sides. Popup `Editable` canvases stay transparent and contain only the popup body; do not rebuild page or App-interface backgrounds, and ignore legacy popup layers such as `Background/AppInterface`, search bars, navigation, bottom tabs, feeds, and page cards. Banner and float directions use their native background layer geometry and style from `layers.json`; a legacy `spec.json` palette may be used only as an optional fallback. Place transparent assets inside `assetPlacement.box` with aspect ratio preserved, `contain` sizing, and center alignment; use `assetBboxPx` only for older reports. Never upload rejected assets.
- Treat editable-side visual QA as a hard completion gate. Export the `Editable` artwork alone at the preview's exact native pixel dimensions, read back every layer's actual absolute geometry and text baseline into the required geometry JSON, and run `node scripts/figma-visual-qa.mjs`. Inspect both `overlay-50.png` and `difference-heatmap.png`; side-by-side inspection alone is insufficient. Similarity must be at least 95%, popup edge error at most 4 px, Banner/float edge error at most 2 px, size error at most 1%, and text-baseline error at most 2 px. Missing accepted or critical assets, visible rejected assets, residual rectangular mattes, artwork Auto Layout, generic placeholders, non-official functional icons, wrong canvas size, or an unlocked/visible `Visual Base` fail QA. Fix duplicated OCR, clipping, wrong fonts, icon distortion, residual text, z-order, and all position drift. Do not hide `Editable Elements` or reveal `Visual Base` as a workaround. Pass the generated report to `figma-sync-progress.mjs complete --qa-report ...`; without that evidence the direction must remain incomplete.

## Recovery

- If the runtime reports missing login, run setup and then rerun the same command.
- Retain failure screenshots and continue later directions. New directions receive the two-attempt stage budgets above; historical failures run last with one final attempt. Remaining failures do not block verified ready directions from continuing to Figma.
- If Figma fails, record the direction failure in `figma-sync-state.json`; do not rerun collection or generation. Resume that direction from its existing manifest artifacts and recorded node ID.
- If the 10:30 run was missed, notify once and wait for explicit user approval before launching a catch-up run.
