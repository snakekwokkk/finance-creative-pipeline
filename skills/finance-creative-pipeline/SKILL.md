# Finance Creative Pipeline

Use the deterministic local runtime for web collection, ChatGPT Web generation, and post-generation visual decomposition. Use Figma MCP tools only after the runtime reaches `awaiting_figma`; sync only `ready` directions that each have a valid `preview.png`, `layers.json`, and `layers/decomposition-report.json`.

## Run order

1. Ensure dependencies exist with `npm install` in the plugin root when `node_modules` is absent.
2. For first use or expired sessions, run `node scripts/setup-login.mjs` for Huaban plus ChatGPT. Let the user complete both logins in the visible browser.
3. Run `node scripts/run.mjs` for the normal Huaban 10-reference/10-direction workflow. Add `--test` for the 1-reference/1-popup trial, use `--types popup,banner,float` for an isolated three-type validation run, or use `--types popup,banner,float --collection-only --visible` to collect and content-audit one Huaban reference per type before stopping without generation, decomposition, or Figma work. Normal and scheduled runs use a visible dedicated Chrome by default.
4. Read the emitted `runDir`, `figma-manifest.json`, and the `layers.json` plus `layers/decomposition-report.json` referenced by each `ready` direction. Do not start Figma work unless the run status is `awaiting_figma`; retained failures are audit records and must not be synced.
5. Follow [figma-sync.md](references/figma-sync.md) to create the dated section, upload the preview and extracted assets, rebuild OCR text natively, and verify screenshots.
6. After all Figma nodes and images are verified, run `node scripts/mark-figma-complete.mjs --date YYYY-MM-DD --section-id NODE_ID --section-name "SECTION_NAME" --direction-ids ID1,ID2 --uploaded-assets N`. Do not mark the run complete before visual verification.

## Hard requirements

- Use the persistent Chrome profile stored outside the plugin. Never export or share it.
- Keep normal, scheduled, and resumed runs in `browser.mode: "visible"` so Huaban and ChatGPT share the same authenticated persistent-profile behavior. Do not automatically hide or minimize the browser. Treat `headless` and `background` as opt-in diagnostic modes only: Huaban may reject headless mode with HTTP 405, while ChatGPT may lose its authenticated session in the macOS background-launch mode.
- Launch the dedicated Chrome process at most once per workflow run. Hold the global workflow lock until the browser closes, create the selected source search tab, its detail tab, and the ChatGPT tab together at startup, and reuse them for all directions and retries. If another run is already active or the browser fails, stop instead of opening a second Chrome window.
- Use ChatGPT Web for analysis and image generation. Do not call Codex image generation as a fallback.
- Create or reuse exactly one dated ChatGPT project named `<chatgpt.projectNamePrefix> YYYY-MM-DD` for each run date. Persist the verified project URL in `figma-manifest.json` and `run.json`; on resume, reopen it instead of creating another project. If Projects is unavailable or the project URL cannot be verified, stop instead of falling back to ungrouped root-level chats.
- Create or reuse the dated ChatGPT project before reference collection. Keep the three optional content-audit chats named `采集筛选-弹窗`, `采集筛选-Banner`, and `采集筛选-浮窗` inside that same project, persist their URLs in `reference-audit-chats.json`, and reuse them on resume. Never create root-level audit or generation chats.
- Use exactly one project chat per creative direction. Keep direct reference-conditioned preview generation, semantic layer JSON, optional complex-frame reconstruction, and direction retries in that same chat. Persist each direction chat URL immediately after it becomes available and reopen it when resuming. Start the next chat only when moving to the next direction; never create separate decomposition or asset chats.
- Explicitly rename every direction chat through ChatGPT's conversation menu and persist the verified title in the manifest. Use type-local numbering: `弹窗1` through `弹窗6`, `Banner1` through `Banner2`, and `浮窗1` through `浮窗2`; isolated validation runs start each included type at 1. Do not rely on ChatGPT's auto-generated titles.
- Upload each direction's reference through ChatGPT's image-specific input exactly once on the normal successful path. Verify the expected filename, visible removable attachment, rendered thumbnail, and enabled send control, then use that same message to ask ChatGPT to analyze the reference internally and directly generate the preview. Do not request or display an intermediate analysis, design spec, image prompt, or JSON, and do not upload the reference again in a separate preview-generation turn. On an ordinary generation retry, reuse the reference already present in that direction chat; re-upload only when ChatGPT explicitly reports that the reference image is missing.
- Generate exactly one complete preview image. First extract complex raster visuals directly from that preview's source pixels. When a large connected framework encloses multiple editable text, button, card, or decoration layers and source-pixel extraction cannot remove those overlays, ChatGPT may reconstruct only that framework in the same direction chat by removing the overlays and filling the hidden material. Do not re-upload the reference or preview for this fallback. Keep visually connected hero objects together as one raster group, and separate only independently movable complex visuals.
- Treat the Huaban reference as visual direction rather than a template. Preserve a similar financial visual category, material feel, color relationship, and information hierarchy where useful, while redesigning concrete shape details, copy, and local layout rather than copying the full design.
- For popup directions, generate only the popup body: the card, its shadow, attached or overflowing hero, internal content, CTA, and popup-owned decorations. Leave only a clean uniform safety margin outside it. Never generate an App page, search bar, navigation, bottom tabs, feeds, page cards, charts, or blurred interface behind the popup.
- After each preview is saved, request semantic review in the same ChatGPT conversation without uploading the preview again. Save layer roles, normalized boxes, editable types, OCR copy, z-order, confidence, and a short `assetPrompt` for every complex raster asset to `layers.json`.
- Keep the semantic-review response readable in ChatGPT: request exactly three display lines consisting of `DECOMPOSE_START`, one complete minified JSON line, and `DECOMPOSE_END`. Do not remove layer data or rely on unsupported collapsible HTML; parse the compact JSON and save it normally to `layers.json`.
- Detect semantic-review completion from the latest valid non-empty `DECOMPOSE_START`/`DECOMPOSE_END` block across the saved conversation, not from one fragile assistant-message selector or the disappearance of ChatGPT's stop control. Ignore the empty example in the user prompt. On resume and before every retry, scan the existing direction chat first and consume its newest complete marked JSON immediately; never submit another decomposition request when a valid result is already present.
- Classify by an explicit 80% native-fidelity threshold. Complex hero visuals, 3D objects, people, mascots, illustrations, gradient folds, embossed badges, glossy envelopes, and other objects that cannot be faithfully rebuilt with Figma text and basic vectors at 0.8 fidelity must use `raster`; simple geometry, ordinary icons, charts, lines, and plain buttons may remain native `vector` or `text`. Keep connected complex hero objects in one raster asset so their geometry cannot drift. Split only spatially independent complex objects; do not include copy, buttons, or reconstructable panels in the raster asset, and do not increase the asset count for objects that are genuinely simple.
- Describe every ordinary functional icon as `kind: "icon"` with `icon.query` containing two to four concise English semantic terms, `icon.style` set to `line` or `fill`, and `icon.color` copied from the preview. During Figma reconstruction, search the bundled Remix Icon package first and import the closest semantically correct official SVG as an editable vector. Never invent an icon-library filename, trace an icon by hand, or leave a generic rectangle, sparkle, chevron, or improvised path when Remix Icon has a suitable match. Do not replace logos, brand marks, complex illustrations, or unique campaign symbols with library icons.
- For each raster layer, use its tight bbox plus a small safety margin and run the bundled source-pixel background matting extractor first. Local processing may infer Alpha from the surrounding background, trim transparent margins, and measure Alpha/border quality. If the source crop is usable but tight or touches its crop boundary, retain it with explicit warnings instead of discarding a legitimately small element.
- Use ChatGPT reconstruction only for large composite frameworks that contain multiple declared editable layers or when no usable source-pixel asset can be recovered. Ask it to remove text and overlays, fill the occluded material, and place the isolated subject on a uniform background; locally derive Alpha afterward. Record `engine: chatgpt-reconstructed-matting`, `sourcePixelExact: false`, and the retained source fallback when available. Never describe a reconstructed asset as source-pixel exact.
- Reject only assets that are empty, lack usable Alpha after local matting, or have no recoverable subject. Continue processing every other raster after one fails. A report may be `partial` when at least one complex asset is usable; retain every accepted asset and every failed attempt for audit.
- Treat `decomposition-report.json` warnings and limitations as binding evidence. Accepted source assets report `engine: native-source-pixel-matting` and `sourcePixelExact: true`; accepted reconstructed assets report `engine: chatgpt-reconstructed-matting` and `reconstructedByChatGpt: true`. Tight crops and source fallbacks may list `suppressesLayerIds` so Figma does not duplicate content already baked into the retained raster.
- Do not bypass login, CAPTCHA, WAF, download restrictions, paid assets, or security interstitials.
- Collect from Huaban only. Use Chinese type search plans: six popup references, two Banner references, and two floating-window references. Give each direction exactly one matching image and rotate keywords after at most three candidates. Floating-window references may be a complete entry, a single finance-related 3D/illustration asset, or an asset-plus-button composition.
- Treat source titles as weak metadata. Hard-reject only titles that explicitly identify a background, template, full page, unrelated industry, or another clearly invalid form. For floats, buttons, badges, coins, red envelopes, 3D assets, and illustrations are valid standalone references when they carry financial meaning. Route empty titles, filenames, `IMG_*`, and titles missing finance or format terms to image-content review instead of rejecting them.
- For every missing direction, scan at most 30 unseen Pins across rotated queries, temporarily download at most eight candidates that pass technical gates, and review at most three images per ChatGPT Web batch. Keep popup and Banner minimum width at 720 px by default and require Banner aspect ratio of at least 1.5. Floating references have no normal width, aspect-ratio, or Alpha gate at collection time: accept a compact financial 3D/illustration subject on a flat canvas for later transparent extraction, while still rejecting obvious backgrounds and complete pages.
- Make the final reference decision from visible image content. Require `typeMatch`, `completeDesign`, and `financeRelevant`, plus a score of at least 60. Weight the score toward financial relevance: `financeRelevant` 50%, `typeMatch` 20%, `completeDesign` 15%, `structureValid` 10%, and `usableReference` 5%. Treat `structureValid` and `usableReference` as soft signals rather than hard rejection gates. Treat any visible Arabic numeral, the Chinese character `元`, `¥`, `$`, `%`, coins, coupons, dashboard visuals, red envelopes, or interest/fee wording as a finance-relevant signal. For popups require a complete modal/card and content hierarchy; for Banners require a finished horizontal finance-marketing composition; for floats require a complete independent finance-operations entry or campaign subject. Reject backgrounds, empty templates, atomic buttons/icons/elements, unrelated industries, QR codes, or clearly low-quality materials. The audit no longer globally rejects real logos or financial-promotional wording such as guaranteed approval, fixed returns, or fabricated endorsements; judge those according to the visible design and the task context.
- Delete rejected temporary candidate files after recording their Pin, source, title, visual score, audit chat, and reasons in the rejection ledger. Move only selected originals into `references/`; each direction still receives exactly one reference. Reuse accepted `contentAudit` results on resume and re-review cached references that predate content auditing.
- Give content-review submission at most two attempts per batch. Login expiry, CAPTCHA, WAF, project-access, and permission errors remain global user-action blockers. If the scan/download budgets end without a passing candidate, record `stage: "collection"`, skip that direction, and continue remaining directions and all valid Figma work. Never reuse another direction's reference to fill the gap.
- Before downloading, reject previously recorded Huaban Pin IDs in `reference-history.json` and scroll deeper for unseen results. Reject identical images by SHA-256 or identical aHash plus matching aspect ratio.
- Open each accepted source detail page and select the highest-resolution URL exposed by its visible main image through `currentSrc`, `src`, or `srcset`. Require the configured minimum width (720 px by default) for popup and Banner references only; floats are content-gated and may be smaller. Retain the reference type, search query, list thumbnail URL, selected image URL, dimensions, and source URL. Never synthesize Huaban CDN URLs.
- Keep generated content brand-neutral and reject real logos, real brand names, copied copy, guaranteed approvals, fixed returns, or fabricated regulatory endorsements.
- Resume from `run.json` and `figma-manifest.json`; never duplicate successful directions or Figma date sections. After cached references are re-audited, read the daily `reference-rejections.json`; if a `ready` direction cites a newly rejected source URL, invalidate and regenerate only that direction with its newly accepted replacement reference, including its preview, semantic layers, and transparent assets. Keep every unrelated complete direction intact. Treat legacy `stage: "analysis"` failures as pending direct-generation work with the normal generation attempt budget.
- Give preview generation at most two total attempts, each with a five-minute wait limit. Record an exhausted direction in `figma-manifest.json.failures` and continue later directions.
- Give semantic decomposition its own budget of at most two total attempts, each with a five-minute wait limit. Once `preview.png` is valid, never regenerate it because decomposition timed out. On a missing response, reload the same saved direction chat and scan for a complete marked result before any resend. Only when no valid result exists may the runtime reupload the existing preview if needed and resend the semantic decomposition prompt.
- Attempt every declared raster independently. Reuse accepted source or reconstructed assets with supported provenance, retry only the failed asset, and never let one failure prevent later assets from being attempted. Partial directions may continue when they retain at least one usable complex asset.
- Snapshot historical failed directions at run start, process them after all new pending directions, and give each historical direction only one total attempt for its remaining ChatGPT stage. After that final historical pass, end the day's ChatGPT phase. Preserve remaining failures for audit, set the run to `awaiting_figma` when at least one verified `ready` direction exists, and continue Figma sync using only those ready directions.
- Login expiry, CAPTCHA, WAF, security checks, access denial, and permission errors are user-action blockers, not direction failures. Stop immediately and notify the user instead of retrying or skipping past them.
- For Figma writes, load and follow `figma-use` and `figma-generate-design`; work incrementally and return every created or mutated node ID.
- Preserve the two-up contract in Figma: `Preview` is the visible flattened design on the left, while `Editable` on the right must visibly render the reconstruction from accepted `native-source-pixel-asset` and `chatgpt-reconstructed-asset` PNGs plus native text and vectors. Skip every native layer ID listed in an accepted raster's `suppressesLayerIds`; that content is already baked into the retained tight-crop or fallback image. Keep `Visual Base` locked but hidden as an inspection reference; never show the same flattened preview on both sides. Popup `Editable` canvases stay transparent and contain only the popup body; do not rebuild page or App-interface backgrounds, and ignore legacy popup layers such as `Background/AppInterface`, search bars, navigation, bottom tabs, feeds, and page cards. Banner and float directions use their native background layer geometry and style from `layers.json`; a legacy `spec.json` palette may be used only as an optional fallback. Place transparent assets inside `assetPlacement.box` with aspect ratio preserved, `contain` sizing, and center alignment; use `assetBboxPx` only for older reports. Never upload rejected assets.
- Treat editable-side visual QA as a completion gate. Fix or hide duplicated background OCR, text that exceeds its declared bbox, malformed generic vector placeholders, incorrectly matched or distorted Remix Icons, residual text showing through translucent cards, and incorrect z-order. Do not hide `Editable Elements` to make the screenshot pass, and do not mark Figma complete while the right side is identical to the preview or visibly broken.

## Recovery

- If the runtime reports missing login, run setup and then rerun the same command.
- Retain failure screenshots and continue later directions. New directions receive the two-attempt stage budgets above; historical failures run last with one final attempt. Remaining failures do not block verified ready directions from continuing to Figma.
- If Figma fails, do not rerun collection or generation. Resume from the existing manifest.
- If the 10:30 run was missed, notify once and wait for explicit user approval before launching a catch-up run.
